# Phase B: trusted Docker smoke worker implementation plan

> Execution: inline with executing-plans and test-driven-development; use the existing isolated worktree. Review before handoff.

**Goal:** run one CPU dummy episode in two distinct containers, with host-owned lifecycle timing, strict Docker command construction, failure classification and scoped cleanup.

**Architecture:** `submission_worker/docker_runtime.py` wraps a local Docker CLI using argv (never shell). `submission_worker/controller.py` creates an internal network and episode volume, runs trusted initialization then benchmark/algorithm containers, reads only the trusted summary and always attempts cleanup. `benchmark/smoke_container_service.py` supplies a test-only synthetic renderer plus NumPy kernels using the real runner/gateway/evaluator. Public submission execution stays disabled. Installation was explicitly deferred by the user during execution; finish local development and retain live Docker acceptance as outstanding.

**Tech stack:** Python 3.10 stdlib controller, Docker Engine local Unix socket, existing FastAPI/NumPy/Pillow smoke environment.

**Spec:** `docs/superpowers/specs/2026-10-21-objview-submission-platform-design.md` §§8,10–11,15.0,17B. This plan implements the trusted development subset, not full security certification or build/upload infrastructure.

## Global constraints

- CPU/dummy chain acceptance only; all reports have `mode=smoke_test`, `official_result=false`, `leaderboard_eligible=false`.
- Only explicit trusted smoke execution, never uploaded/untrusted images. No implicit tag pulls: resolve immutable local `sha256:<64 hex>` image IDs before starting.
- Local Unix Docker endpoint only. No user-supplied Docker arguments, shell command, bind mount, device, GPU, privileges or host network.
- Separate containers, internal per-job network (no host published ports), read-only algorithm root and released-volume subpath; no Docker socket in either container.
- Both running containers use UID/GID 65532, cap-drop ALL, no-new-privileges, finite memory/CPU/PIDs/tmpfs, disabled Docker logs. Fixed trusted init creates volume directories with the required ownership.
- Start the monotonic startup timer before `docker start`; retain separate total job and per-step benchmark timing. Do not label container-start API latency as model loading time.
- Always attempt cleanup of exact resources bearing this job's label. Do not prune, remove images, or touch other resources. Cleanup failure makes the job unsuccessful and records remaining resource names.
- Docker CLI command timeouts and overall episode hard deadline; no automatic retries of algorithm failures.
- Standard internal Docker networking is not an audited egress policy; rootless cgroup enforcement and volume-subpath support require real environment validation. Fail closed if required Docker controls cannot be applied.
- Installation authorized by user, but never collect a sudo password or bypass permissions. Prefer rootless once required host packages are available.

Interfaces: `DockerRuntime.call(args, timeout=30) -> str`, `resolve_image(reference) -> str`, `container_args(name, image_id, network, volume, role, label, token_file) -> list[str]`.

- [x] Write failing tests rejecting mutable/malformed image IDs, arbitrary endpoint/argument injection and ensuring no host mounts/published ports; verify limits and read-only algorithm subpath.
- [x] Implement subprocess invocation with `shell=False`, sanitized exceptions, bounded timeout and explicit local Docker socket selection.
- [x] Run unit tests with an injected command executor; these establish command contracts, not real Docker security.

Example assertion:
```python
args = container_args(..., role='algorithm', ...)
assert '--read-only' in args
assert any('volume-subpath=released' in x for x in args)
assert '--privileged' not in args
```

## Task 2: controller lifecycle

Interfaces: `run_smoke(runtime, benchmark_image, algorithm_image, output_dir, timeout_sec=30) -> dict`.

- [x] Test success and failures with a stateful fake Docker boundary: init failure, algorithm nonzero/OOM, benchmark failure, timeout, malformed/non-smoke summary, cleanup failure and foreign ownership.
- [x] Implement states PREPARING → STARTING → RUNNING → SUCCEEDED/FAILED plus cleanup evidence; preserve primary failure even when cleanup also fails.
- [x] Persist a private controller report without token, raw logs, observations or numerical scores; accepted summary must be explicitly smoke, completed and match job ID.
- [x] Include no-retry behavior and exact resource cleanup assertions.

Example assertion:
```python
report = run_smoke(fake, image_id, image_id, new_output_dir)
assert report['leaderboard_eligible'] is False
assert report['cleanup']['complete'] is True
assert fake.resources == {}
```
