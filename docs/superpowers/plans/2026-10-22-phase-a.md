# Phase A: trusted interaction protocol implementation plan

> Execution: execute in this session using the executing-plans workflow, with tests before implementation and per-task verification.

**Goal:** expose the existing episode runner through an authenticated, anonymous HTTP boundary with authoritative server timing.

**Architecture:** a dependency-light state machine owns action acceptance, deadlines and idempotency. A FastAPI adapter provides transport; a trusted interaction adapter connects the existing runner without exposing its filesystem, summaries or oracle RPC. Preserve the legacy research launcher as explicitly trusted-only.

**Tech Stack:** Python 3.10+, unittest, FastAPI, Uvicorn, HTTPX for ASGI tests; existing NumPy/Pillow runner dependencies.

**Spec:** `docs/superpowers/specs/2026-10-21-objview-submission-platform-design.md`

## Global constraints

- No real UID, cache path, oracle API, metrics or raw exception on algorithm HTTP responses.
- Token is injected by controller, never printed; all routes authenticate.
- Server monotonic clock is authoritative. Action fields cannot override timing.
- At most one action per step; idempotent retries cannot advance twice or change measured time.
- 512 feasibility poses/request; 4096/step; 120s action deadline by default.
- Legacy file sessions remain trusted-only and are never mounted for submissions.
- Do not repartition the published 528-object benchmark in this phase. The design's proposed 400/128 split needs dataset-release review before implementation.
- Do not claim container isolation or full benchmark execution from in-process tests.
